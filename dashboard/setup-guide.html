Step-by-step

  1. 1

    Create or pick a Google Cloud project

    1. Open Google Cloud Console and choose Create project (or one you use only for TubeStack).
    2. Name it something clear, like “TubeStack”, then select it in the top bar.
  2. 2

    Enable YouTube Data API v3

    1. Go to APIs & Services → Library.
    2. Search for YouTube Data API v3, open it, and click Enable.
  3. 3

    Create an API key for channel scan & tags

    1. Go to APIs & Services → Credentials → Create credentials → API key.
    2. Recommended: under API restrictions, restrict the key to YouTube Data API v3 only.
    3. Copy the key — it starts with AIza.
  4. 4

    Set up the OAuth consent screen for Google sign-in

    1. Go to APIs & Services → OAuth consent screen and choose External.
    2. Fill in the app name, user support email, and developer contact email.
    3. Under Scopes, add https://www.googleapis.com/auth/youtube.
    Stay in Testing — add yourself, don’t publish.

    While the app is in Testing, only accounts listed as Test users can sign in. Open Audience (or the test-users step), click Add users, and add the full Google email you use in Chrome. Don’t click Publish app unless you intend to go through Google’s verification for a public app — for personal use, Testing is normal.

  5. 5

    Create an OAuth Client ID for Google sign-in

    1. In Credentials, choose Create credentials → OAuth client ID.
    2. Application type: Web application.
    3. Under Authorized redirect URIs, add the redirect URI from Your values exactly.
    4. Create it and copy the Client ID (ends with .apps.googleusercontent.com).

    TubeStack only needs the Client ID. You never paste a client secret into TubeStack.

  6. 6

    Paste into TubeStack and test

    See where to paste below, then run the built-in tests.

Where to paste in TubeStack

During setup

The setup wizard asks for the API key, then the OAuth Client ID, each with a Test button.

Any time later

Dashboard → Settings → Optional integrations → Google (YouTube): paste the key, click Save API key then Test API key; paste the Client ID, click Save Client ID then Test Google sign-in.

Sign-in only

Connect YouTube walks through just the OAuth Client ID and a test sign-in.

Troubleshooting

Google says “Access blocked” or “This app isn’t verified”

Your Google account isn’t listed under Test users on the consent screen (step 4), or the app was published. Add the exact email you sign in with and keep the app in Testing.

Error 400: redirect_uri_mismatch

The OAuth client doesn’t list this install’s redirect URI. Copy it from Your values into Authorized redirect URIs and save. Make sure the client type is Web application. Changes can take a few minutes to apply.

“Test API key” fails

Check that YouTube Data API v3 is enabled in the same project as the key (step 2), that the key was copied completely, and that any API restriction includes YouTube Data API v3.

Requests start failing after heavy use

Google gives each project a free daily YouTube API quota. If it runs out, requests fail until it resets the next day (Pacific time). Usage is visible under APIs & Services → YouTube Data API v3 → Quotas.

I moved my library to a new TubeStack install

TubeStack backups deliberately leave out API keys and the OAuth Client ID. Paste them again on the new install, and add the new install’s redirect URI to your OAuth client (the extension ID changes).

What is sent, and where

  • API key — stored in this browser’s extension storage. Sent only to www.googleapis.com with the request when you run a channel scan, a key test, or a tag/category lookup (video IDs or the channel handle you entered).
  • Google sign-in — happens in Google’s own window, only when you click an action that needs it. TubeStack never sees your password and receives a short-lived access token that it keeps in memory only (not in storage) for up to about 45 minutes. No refresh token or client secret is used.
  • No TubeStack server — requests go directly from your browser to Google. Chrome asks you to allow access to googleapis.com the first time a feature needs it.

AI providers Optional

AI tools (generate categories, AI categorize, Watch State suggestions) can use OpenAI or Anthropic (Claude). Pick one in Settings → AI categorization. TubeStack sends the metadata a tool needs straight from your browser to that provider, only when you run the tool, and always shows a preview before anything in your library changes. Keys stay on this device and are never put in a backup file.

OpenAI API key

  1. Sign in at platform.openai.com (the API platform — not the same product as ChatGPT).
  2. Open API keys and create a secret key. API usage is billed through that account’s credits.
  3. In TubeStack choose Provider: OpenAI in Settings → AI categorization, paste the key, save, and use Test API connection.
ChatGPT Plus is separate.

A ChatGPT subscription doesn’t fund API calls.

Anthropic (Claude) API key

  1. Sign in to the Claude Console (the Anthropic API platform — not the Claude.ai chat app and not Claude Code).
  2. Add API credits under billing, then create an API key under API keys.
  3. In TubeStack choose Provider: Anthropic (Claude), paste the key, pick a model, save, and use Test connection. Requests go only to api.anthropic.com.
A Claude.ai subscription is separate.

Pro, Max and Team plans don’t fund API calls. TubeStack can’t read your Anthropic balance; if credits run out, AI tools say so and nothing in your library changes.
